# LuminousSSS 登录界面 UI 规格

> 目标引擎：团结引擎 2022.3（UGUI）｜设计分辨率：1920×1080 横屏｜美术风格：16-bit 像素（对齐项目既有 V2 素材）
> 本文档描述**已实施**的改版与**待确认**项，所有尺寸都给了取值依据。

---

## 0. 结论先行

登录界面难看的**根因不是配色，是两件事**：

1. **布局整个上下颠倒** —— 标题在屏幕最底、开始按钮在屏幕最顶（详见 §1.1）；
2. **零素材** —— 全部用 `Image` + 纯色直角块拼，而项目 `Assets/Art/V2/UI/` 里本就躺着 12 个现成的像素 UI 素材，一个都没引用。

改版做法：**复用项目已有素材**（风格天然统一、零版权风险）重建界面，修正布局，补齐按钮四态。

## 1. 现状诊断

### 1.1 P0：布局上下颠倒

`GameSceneBuilder.CreateUI` 用的是**左上角锚点**，`centerPos.y` 语义是"距屏幕顶部"（y 越小越靠上）：

```csharp
rt.anchorMin = rt.anchorMax = new Vector2(0f, 1f);
rt.anchoredPosition = new Vector2(centerPos.x, -centerPos.y);   // y 向下为正
```

但 `BuildLoginScene` 里的 y 值是按"距屏幕底部"写的，于是整体镜像了：

| 元素 | 原代码 y | 实际落点 | 设计文档 v0.1 §3.2 要求 |
|---|---|---|---|
| StartButton / SettingsButton | 90 | **屏幕最顶部** | 最底部 |
| CharacterName | 190 | 上部 | 立绘正下方 |
| Portrait | 560 | 中部 ✅ | 中部 ✅ |
| Title | 960 | **屏幕最底部** | 最顶部 |
| TopBar | 1000 | 最底部（与标题重叠） | — |

### 1.2 P0：零素材

`Assets/Art/V2/UI/` 已有：羊皮纸对话框、木纹按钮（常态 + 选中态）、齿轮 / 闪电 / 心 / 问号图标、格子、体力条。登录界面全部未使用。

### 1.3 其余问题

| 级别 | 问题 | 影响 |
|---|---|---|
| P1 | 按钮只有默认色，无 Hover／Pressed／Disabled | 点击零反馈 |
| P1 | 无容器与层级，元素直接漂在纯色背景上 | 缺少焦点 |
| P2 | 字号 96 / 60 / 56 / 44 / 40，五档但无规律 | 层级读不出来 |

## 3. 状态矩阵

| 元素 | Normal | Highlighted | Pressed | Disabled | Selected |
|---|---|---|---|---|---|
| StartButton | `1,1,1` | `1,0.97,0.88` 暖亮 | `0.76,0.74,0.68` 压暗 | `0.5×alpha 0.5` | 同 Normal |
| SettingsButton | `0.84,0.82,0.78` | 同上（乘算） | 同上 | 同上 | 同 Normal |
| Prev/Next | `1,1,1` | 同上 | 同上 | 同上 | 同 Normal |
| 弹窗开关·开 | 黄框底板 | — | 压暗 | — | — |
| 弹窗开关·关 | 木纹底板 | — | 压暗 | — | — |

- 颜色是**乘**到底板上的，主/次按钮共用一套 `ColorBlock`，层级只靠 `Image.color` 区分。
- 开关的"开/关"**换底板**而不是只换 tint：木纹本身深浅就有变化，纯 tint 区分度不够。
- `fadeDuration = 0.08s`，按压反馈要跟手，超过 0.1s 会觉得粘。

## 4. 九宫格参数表

**边界值一律写四个具名值（左/上/右/下），不写位置序列** —— 四家引擎的顺序不同，写序列必然接反：

| 引擎 | 顺序 |
|---|---|
| Unity / 团结引擎 | **左 / 下 / 右 / 上** ← 本项目 |
| Godot 4 · Unreal | 左 / 上 / 右 / 下 |
| Cocos Creator | 左 / 右 / 上 / 下 |

| 素材 | 原始尺寸 | 左 | 上 | 右 | 下 | 依据 |
|---|---|---|---|---|---|---|
| `v2_ui_button_wood` | 257×85 | 12 | 12 | 12 | 12 | 圆角在 x=9 结束、描边 6px，取 12 留 3px 余量 |
| `v2_ui_button_selected` | 258×94 | 14 | 14 | 14 | 14 | 多一圈 3px 黄框，需多留 2px |
| `v2_ui_dialog_panel` | 1411×372 | 26 | 26 | 26 | 26 | 木框≈18px、四角铆钉≈22px |
| `v2_ui_dialog_panel_tall` | 1411×1411 | 26 | 26 | 26 | 26 | 同上 |

四值全对称，正好绕开顺序陷阱。

### 4.1 PPU 补偿（关键，漏了边框会粗 1.56 倍）

素材 PPU=64，Canvas `referencePixelsPerUnit`=100。不补偿的话 `spriteBorder` 显示尺寸 =
`12 × (100/64) = 18.75px`，边框变粗且像素不再是 1:1。

```csharp
img.type = Image.Type.Sliced;
img.pixelsPerUnitMultiplier = 100f / 64f;   // = 1.5625，抵消 PPU 差
```

补偿后 border 按素材原始像素显示，硬边不糊。

### 4.2 边界已写进导入设置

`PixelArtImporter`（AssetPostprocessor）里维护了一张表，素材一导入就自动带好 border，
美术重新导出素材也不会丢：

```csharp
{ "v2_ui_button_wood",     new Vector4(12, 12, 12, 12) },   // 左 下 右 上
{ "v2_ui_button_selected", new Vector4(14, 14, 14, 14) },
{ "v2_ui_dialog_panel",    new Vector4(26, 26, 26, 26) },
```

| Pixels Per Unit Multiplier | 1.5625 | 同上 |

### 6.1 为什么 Match 从 0.5 改成 1.0

横屏游戏必须按**高度**适配，否则超宽屏会裁掉内容：

| 屏幕 | Match=0.5 的虚拟画布 | 结果 | Match=1.0 的虚拟画布 | 结果 |
|---|---|---|---|---|
| 1920×1080 | 1920×1080 | ✅ | 1920×1080 | ✅ |
| 2560×1080（21:9）| 2217×**935** | ❌ 底部按钮被裁 | 2560×1080 | ✅ 左右留白 |
| 1440×1080（4:3）| 1663×1247 | ✅ | 1440×1080 | ✅ 左右留白 |

Match=1.0 让所有 16:9 分辨率都精确映射到 1920×1080 虚拟画布，其余比例一律左右留白、内容零裁切。
