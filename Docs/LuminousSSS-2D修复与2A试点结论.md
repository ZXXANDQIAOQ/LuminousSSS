**修法说明**

- **花草（2D-02/03）**：原图是 AI 生成的「伪像素」——看着像像素画，实际每张 1200~1300 个渐变色。
  直接 alpha 二值化会留下发毛的轮廓，所以**重画**：确定的调色板 + 硬边 + 逐片花瓣描边。
- **立绘（2D-04）**：需求写明「硬边化，不重画」，所以只对 alpha 做二值化（阈值 128）。
  ⚠️ **副作用**：原图边缘是抗锯齿柔边，二值化后轮廓会有轻微阶梯感；因为登录界面按 1:2 用
  Point 过滤显示，硬边比柔边更合适，但如果观感不接受，可以改回阈值更低的版本。
- **招牌（2D-05）**：文字是「白色浮雕 + 浅蓝描边」，且**带内还压着雨篷垂齿与窗内货物**。
  做法是逐列在文字带上下各取一个确实是玻璃的像素、线性插出玻璃基准色，
  再把「与基准色偏差过大」的像素判为文字替换掉，最后做一次纵向中值平滑。

**未做**：2D-01（行走帧重画）属于 2A 范围，见下。

## 二、2A 试点结论：⚠️ **程序化生成的角色帧达不到现有素材的水准，建议转交角色美术**

按你的要求先跑了「1 个角色、全方向」的试点：农夫，**4 方向 × 6 帧 = 24 帧**，
全部满足硬性规格：

| 校验项 | 结果 |
|---|---|
| 画布 | ✅ 24 帧全 64×112 |
| 脚底基线 | ✅ 24 帧全 y=109 |
| 水平居中 | ✅ 偏移 ≤1px |
| 硬边（半透明像素） | ✅ **0.00%** |
| 24 帧特征一致性 | ✅ **由构造保证**——同一套骨架 + 同一套配色常量，物理上不可能出现「某方向多顶帽子」 |
| 自动校验 | `check_walk_consistency.py --canvas 64x112 --baseline 109` → **几何/硬边/居中全部通过**；仅剩 2 条「疑似调色板漂移」（正/侧视衬衫明暗因手臂数量不同而略有差异，属预期内的误报） |
| 配色同源 | ✅ 取自现有 `v2_walk_down_01.png` 实测主色（发 `#7A2A0E`／肤 `#F0A060`／衫 `#2E A82A`／背带裤 `#2440A8`／裤 `#2A66C8`／靴 `#5A2A10`） |

**但质量不达标。** 与现有农夫帧并排（`preview/08_2a_pilot_vs_existing.png`）：

| 对比项 | 现有帧 | 试点帧 |
|---|---|---|
| 头发 | 有发丝分组、明暗层次 | 一整块，像头盔 |
| 面部 | 有眉、眼白/虹膜/瞳孔/高光、鼻影 | 眼睛像贴上去的白色椭圆 |
| 背带裤 | 有口袋、扣子、缝线、裤腿分缝 | 一块圆角蓝块 |
| 侧面 | 有鼻梁、下颌、耳廓 | 脸是一个从头发里伸出来的椭圆 |
| 双腿 | 有分缝与明暗 | 糊成一整块 |

**根因**：我用的是几何图元（圆角矩形 + 椭圆）拼装，它能保证**结构正确与绝对一致**，
但画不出 AI 手绘素材里的层次与细节。这不是「再调调」能补上的差距——
在 64×112 上做真正的像素角色，是手绘功夫，不是参数调优。

**结论与建议**

- 2A 的**角色插画本体**建议转给 `cocos-game-artist`（或你已有的画师/AI 流程）。
- 我这边已经就绪的、转交后立刻能用的部分：
  - 规格（画布 / 基线 / 居中 / 命名 / 帧数）——`Docs/LuminousSSS-角色动画帧规格.md`
  - 归一脚本 `Tools/normalize_walk_frames.py`（任意尺寸进去，64×112 / y=109 出来）
  - **一致性闸门** `Tools/check_walk_consistency.py`——就是上次逮出草帽那个，
    可以直接卡「退回重做」
  - 硬边校验 `Tools/verify_hardedge.py`
- 如果你接受**更简单的经典 16-bit 风格**（与现有 AI 素材不同但内部完全统一），
  我可以继续把试点推进到 4 个角色；**但请先看 `preview/08` 再决定**——
  我不建议在没确认风格的前提下铺开 96 帧。

> 试点原始帧放在 `Docs/pilot_walk_farmer/`（**故意不放进 `Assets/`**，
> 避免被误当成可用素材引用）。要复现：`python3 Tools/gen_farmer_pilot.py`。

## 四、验证

- 全部 8 张 2D 素材：`Tools/verify_hardedge.py` 半透明占比 **0.00%**。
- 试点 24 帧：`Tools/check_walk_consistency.py --canvas 64x112 --baseline 109` 退出码 **3**，
  其中 **26 项为几何/硬边类，已全部清零**；余 2 项是「疑似调色板漂移」——
  正视/背视有两条手臂、侧视只有一条，导致衬衫的亮绿 `#20A020` 只出现在 down/up、
  暗绿 `#106010` 只出现在 left/right。这是侧视的**合理差异**，非特征漂移，人工确认即可放行。
  修正过程：初版底边落在 y=111（靴尖椭圆超出基线），已改为按「描边前脚底 = 107」推算，
  外描边 +2 后精确落在 109；侧视主体中心偏 -1.5px，已加自动居中后处理补正。
- **未在团结引擎内编译渲染**（生成环境无引擎），观感需你本地确认。
