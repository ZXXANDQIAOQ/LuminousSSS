# FarmScene 行走动画优化 — 诊断与替换说明

> 针对 LuminousSSS main 分支（v0.4.1）第二个场景（FarmScene）角色行走问题。
> 改动只涉及 3 个文件：2 个替换 + 1 个新增。**未改动任何美术素材与登录界面逻辑。**

---

## 一、诊断结果（4 个问题，均已验证）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **女巫动画引用悬空**：`witch_idle.anim` / `witch_walk_down.anim` 引用的 4 个 sprite GUID（48aba982…、2cacc4f6…、4f461647…、4d2e24e6…）在整个仓库里找不到对应 `.meta` 文件。动画播放时会把 SpriteRenderer.sprite 置空 → 走动时角色消失/闪烁 | 全仓库 grep GUID 只命中这 2 个 anim 文件和 SampleScene.scene，无任何素材 meta |
| 2 | **只有向下一个方向**：AnimatorController 仅 Idle↔Walk 两态，向上/左/右走全部播「向下走」动画；`FacingUp` 参数建了却没有过渡使用 | 旧 `EnsureWitchController` 代码 |
| 3 | **四方向 6 帧行走素材完全闲置**：`Assets/Art/V2/Characters/v2_walk_{down,up,left,right}_01~06.png` 共 24 张现成帧，一个都没被引用 | 素材目录 vs 动画引用 |
| 4 | **另外 3 个角色无任何行走动画**：农夫/雨女/冒险者只有单张静态图 + flipX，移动时是纯「滑步」 | `PlayerAppearance.Entry` 无 controller |

---

## 二、优化方案

### 改动总览

| 文件 | 动作 | 说明 |
|---|---|---|
| `Assets/Scripts/Gameplay/PlayerController.cs` | **替换** | 只负责移动和记录朝向，删掉 `bodyRenderer`/`animator` 字段，公开 `Facing` / `IsMoving` 属性 |
| `Assets/Scripts/Gameplay/CharacterAnimDriver.cs` | **新增** | 动画驱动：女巫走四方向 Animator；静态角色走 flipX + 走路小跳（bob） |
| `Assets/Editor/GameSceneBuilder.cs` | **替换** | ① 新增 `EnsureWitchAnimations()`：用现成素材重写 idle + 四方向行走 clip；② `EnsureWitchController()` 重建成 Idle + WalkDown/Up/Left/Right 状态机；③ Player 挂 CharacterAnimDriver |

### 效果

- **女巫**：待机播 idle 两帧呼吸循环；走动时按方向播对应的 6 帧行走（上/下/左/右各自正确，不再全是向下那套）；边走边换方向即时切换；停下平滑回 Idle。左右有专门帧，不再翻转。
- **农夫/雨女/冒险者**：左右走 flipX 转向；走动时身体按 8Hz 上下小跳（幅度约 4 像素），每步「落地」一次；停下平滑回位。消除滑步感。
- 行走小跳改的是 Visual 子物体的 localPosition，**不影响物理移动和碰撞**。

### 技术要点（小白可跳过）

- 动画剪辑用 `AnimationUtility.SetObjectReferenceCurve` + `EditorCurveBinding.PPtrCurve("", typeof(SpriteRenderer), "m_Sprite")` 创建，PPtr 曲线整体重设 → 旧悬空引用被清掉；文件名不变（`witch_idle.anim` / `witch_walk_down.anim` 保留，新增 3 个），SampleScene 里的引用不会断。
- 状态机参数：`Speed`(0/1)、`MoveX`(-1/0/1)、`MoveY`(-1/0/1)。PlayerController 记录的朝向是主轴单位向量（水平优先），所以 MoveX/MoveY 同一时刻只有一个非零，过渡条件只需 2 个（如 `Speed>0.01 && MoveY<-0.5`）。
- 生成器幂等：重复执行先清空 5 个状态的 transitions 再重建，不会累积重复过渡；`witch_*.anim` 已存在时走 `SetDirty` 覆盖而非新建。

## 三、替换步骤（重要：必须删旧场景才能生效）

FarmScene 是本地自动生成的产物（Git 里没有），生成器只在 LoginScene 不存在时才重建，所以**要手动删掉旧场景触发重新生成**：

1. 关闭 Unity 编辑器。
2. 把 3 个文件放进工程（保持目录结构）：
   - `PlayerController.cs` → `Assets/Scripts/Gameplay/`（覆盖）
   - `CharacterAnimDriver.cs` → `Assets/Scripts/Gameplay/`（新增）
   - `GameSceneBuilder.cs` → `Assets/Editor/`（覆盖）
3. 备份后删除这两个本地生成文件：
   - `Assets/Scenes/LoginScene.scene`
   - `Assets/Scenes/FarmScene.scene`
   
   > 它们是生成器产物，删除后会自动重建；若你手动改过场景内容，先自行备份。
4. 重新打开工程，等 Console 出现 `场景生成完成`（或手动点菜单 `Tools/LuminousSSS/一键生成（资源 + 场景）`）。
5. 点播放，走一遍：选女巫 → 开始游戏 → WASD 走。

## 五、已知限制与说明

1. **未经 Unity 真机编译验证**：沙箱里没有 Unity/团结引擎，3 个文件已通过 Roslyn 语法解析（0 错误），但 Unity 语义层（API 是否存在、序列化字段）无法在此环境编译。若 Console 报编译错误，把错误信息发我即可定位。
2. **001/002/003 的 bob 是占位方案**：没有他们的四方向行走素材。正式版建议按 v0.2 的套路补 3 套行走帧（或让画师出图），然后把 `PlayerAppearance.Entry.controller` 给他们也配上 AnimatorController（届时 `CharacterAnimDriver` 会自动改走动画路线，bob 代码不用动）。
3. **`PlayerController` 删了 `bodyRenderer`/`animator` 两个 public 字段**：旧场景（SampleScene.scene）里序列化的这两个字段会被 Unity 自动忽略，不报错；FarmScene 重新生成后本来就没有这两个字段。
4. **行走帧序列**按 `01..06` 顺序循环。如果实际帧序不是线性循环（比如第 6 帧是中转帧），打开 `Assets/Animations/witch_walk_down.anim` 在 Animation 窗口里调关键帧顺序即可，不用改代码。
5. `witch_walk_down.anim` 保留旧文件名是为了不破坏 SampleScene 的引用；内容已被整体重写。
