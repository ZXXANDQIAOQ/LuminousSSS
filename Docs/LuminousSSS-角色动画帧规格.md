## 1. 实测证据

### 1.1 P0-1：行走帧画布有 8 种不同尺寸

| 画布 | 帧数 | 文件 |
|---|---|---|
| 51×106 | 1 | `v2_walk_left_05` |
| 51×107 | 2 | `v2_walk_right_05/06` |
| 52×106 | 5 | `v2_walk_left_01/02/03/04/06` |
| 52×107 | 4 | `v2_walk_right_01/02/03/04` |
| 55×108 | 1 | `v2_walk_down_02` |
| 56×108 | 5 | `v2_walk_down_01/03/04/05/06` |
| 60×109 | 4 | `v2_walk_up_01/02/05/06` |
| 61×109 | 1 | `v2_walk_up_03` |
| 62×109 | 1 | `v2_walk_up_04` |

**为什么这会让角色抖**：逐帧播放时 `SpriteRenderer.sprite` 每次换图，**Pivot 是同一个点但贴图内容位置不同** ——
水平方向差最多 11px（51 vs 62），垂直方向差 3px。角色会在原地左右横跳、上下浮。

### 1.2 P0-2：向上方向角色特征漂移

`down` / `left` / `right` 三方向是**棕发无帽**，`up` 方向 6 帧**全部戴黄色草帽**。
这是 AI 逐帧生成时角色描述词没锁死导致的 —— 头也换了（正面 vs 背面），但帽子是凭空多出来的。

### 1.3 P0-3：女巫立绘缺失

| 角色 | 立绘尺寸 | 状态 |
|---|---|---|
| 001 农夫 | 397×1024 | ✅ |

| 004 女巫 | 54×101 | ❌ 用的是行走帧里的 Q 版小人，靠 `displayScale = 0.7` 硬压 |

## 2. 行走帧规格（重画时照此执行）

| 项 | 值 | 依据 |
|---|---|---|
| **画布** | **64×112** | 现有最大帧 62×109，64×112 是最近的 2 的整数倍画布，留 2px 底部余量 |
| **脚底基线** | **y = 109**（从画布顶部数，0-indexed） | 底部留 2px，避免 `Pixel Perfect Camera` 取整时切到脚 |
| **水平基准** | 主体**视觉包围盒中心**对齐画布中心 x = 32 | 不是按图形外接框 —— 侧向帧的包围盒偏一边，按框对齐会歪 |
| **方向顺序** | **下 / 上 / 左 / 右** | 与现有 `v2_walk_{down,up,left,right}_{01..06}` 命名一致 |
| **帧数** | **4 帧**（不是 6） | 触地-过渡-触地-过渡；现有 6 帧里 2 帧其实是待机/转身帧，混进循环会顿 |
| **帧率** | 8 fps | 与现有 `witch_walk_*` 一致 |
| **左右镜像** | 左 → 右可镜像，但**要检查** | 镜像后草帽带、口袋、扣子等不对称细节会翻面，需要逐帧确认 |
| **PPU** | 64 | 项目 `Assets/Art/V2/` 统一值 |
| **格式** | 透明 PNG，硬边（半透明像素 = 0） | 见 `LuminousSSS-UI规格.md` §1 |

> **为什么画布是 64×112 而不是 64×64**：角色含头身高约 108px，64×64 装不下。
> 112 = 108 + 2 底部余量 + 2 取整到 16 的倍数（112 = 16×7）。

### 2.1 检查帧内容的三个像素

拿到任何一帧，放大到 800% 看这三处，任何一处不对就是废帧：

1. **脚底**：靴底最低的一行像素，必须在 y=109。缺 1px 就会在播放时"踩空"。
2. **头顶**：最高一行像素，理想在 y=4~9（身高 100~105px）。
3. **身体中线**：躯干左右边缘的中心，理想在 x=32±1。

## 4. 归一脚本（已经把现有 24 帧修好了）

`Tools/normalize_walk_frames.py` —— 把任意尺寸的行走帧统一到 64×112，脚底对齐到 y=109。

```bash
# 校验（不改文件）
python3 Tools/normalize_walk_frames.py Assets/Art/V2/Characters --check

# 归一输出到新目录
python3 Tools/normalize_walk_frames.py Assets/Art/V2/Characters --out Assets/Art/V2/Characters_norm
```

**本次实跑结果**：

```
画布 64x112 ｜ 脚底基线 y=109（底部留 2 px）
全部合规：24 帧统一到 64x112，脚底同在 y=109
```

**它做了什么**：按 alpha 包围盒裁出主体 → 水平居中到画布中线 → 底边贴到基线 → 其余补透明。
**它没做什么**：不缩放、不重绘、不修内容（**草帽问题它修不了**）。

> 为什么不做缩放：像素游戏缩放会产生非整数像素密度，反而更糊。
> 归一只是"把尺寸不同的图放进同一个相框"，让角色不再横跳。

**重画流程建议**：

1. 先跑一次 `--check`，确认当前状态；
2. 重画的新帧（无论什么尺寸）丢进同一个目录；
3. 跑归一，输出到 `Characters_norm/`；
4. 再跑 `--check` 验收 —— **退出码 0 才算过**；
5. 人工并排看 16 帧，确认特征一致（脚本查不了这个）。
