## 0. 结论先行

0. ⚠️ **最要紧的一条：行走帧命名与代码不一致，不改代码会白做 96 帧。**
   第二批需求要求 `v2_walk_<角色>_<方向>_<nn>.png`（带角色段），
   但 `GameSceneBuilder.EnsureWalkClip()` 写死的是
   `V2/Characters/v2_walk_{dir}_{i:00}.png`（**无角色段**）——
   按文档命名交付，程序一个文件都找不到，只会刷「缺少行走帧」警告。
   且现有集成是**女巫专用**：只有 `witch_walk_*.anim` 四个剪辑 + 一个
   `WitchPlayerController`，四个角色共用同一套帧。
   要真正按角色区分，**必须同步改代码**（详见 §7）。这一条必须先定，再动笔画。

1. **P0-1「行走帧尺寸不统一」是可以当场修好的** —— 我写了归一脚本，24 帧已统一到 **64×112**、脚底同在 **y=109**，实测通过（见 §4）。
2. **P0-2「向上方向戴草帽」归一脚本修不了** —— 那是内容问题不是几何问题，必须重画，验收标准见 §3.3。
3. **先修 P0-1、再重画**：归一后的帧无论怎么重画都不会再抖，重画的帧只要丢进同一个脚本就能保证不改动其它帧。

| 画布 | 帧数 | 文件 |
|---|---|---|
| 51×106 | 1 | `v2_walk_left_05` |
| 51×107 | 2 | `v2_walk_right_05/06` |
| 52×106 | 5 | `v2_walk_left_01/02/03/04/06` |
| 52×107 | 4 | `v2_walk_right_01/02/03/04` |
| 55×108 | 1 | `v2_walk_down_02` |
| 56×108 | 5 | `v2_walk_down_01/03/04/05/06` |
| 60×109 | 4 | `v2_walk_up_01/02/05/06` |
| 61×109 | 1 | `v2_walk_up_03` |
| 62×109 | 1 | `v2_walk_up_04` |

**为什么这会让角色抖**：逐帧播放时 `SpriteRenderer.sprite` 每次换图，**Pivot 是同一个点但贴图内容位置不同** ——
水平方向差最多 11px（51 vs 62），垂直方向差 3px。角色会在原地左右横跳、上下浮。

### 1.2 P0-2：向上方向角色特征漂移

`down` / `left` / `right` 三方向是**棕发无帽**，`up` 方向 6 帧**全部戴黄色草帽**。
这是 AI 逐帧生成时角色描述词没锁死导致的 —— 头也换了（正面 vs 背面），但帽子是凭空多出来的。

### 1.3 P0-3：女巫立绘缺失

| 角色 | 立绘尺寸 | 状态 |

## 2. 行走帧规格（重画时照此执行）

| 项 | 值 | 依据 |
|---|---|---|
| **画布** | **64×112** | 现有最大帧 62×109，64×112 是最近的 2 的整数倍画布，留 2px 底部余量 |
| **脚底基线** | **y = 109**（从画布顶部数，0-indexed） | 底部留 2px，避免 `Pixel Perfect Camera` 取整时切到脚 |
| **水平基准** | 主体**视觉包围盒中心**对齐画布中心 x = 32 | 不是按图形外接框 —— 侧向帧的包围盒偏一边，按框对齐会歪 |
| **方向顺序** | **下 / 上 / 左 / 右** | 与现有 `v2_walk_{down,up,left,right}_{01..06}` 命名一致 |
| **帧数** | **6 帧 / 方向**（下、上、左、右） | ⚠️ 本文档 v0.8 原建议 4 帧，**现更正为 6** —— `GameSceneBuilder.EnsureWalkClip()` 硬编码循环 6 次，交付 4 帧会报警且动画不完整。要么 6 帧（代码零改动），要么改代码，别只改素材 |
| **帧率** | 8 fps | 与现有 `witch_walk_*` 一致 |
| **左右镜像** | 左 → 右可镜像，但**要检查** | 镜像后草帽带、口袋、扣子等不对称细节会翻面，需要逐帧确认 |
| **PPU** | 64 | 项目 `Assets/Art/V2/` 统一值 |
| **格式** | 透明 PNG，硬边（半透明像素 = 0） | 见 `LuminousSSS-UI规格.md` §1 |

> **为什么画布是 64×112 而不是 64×64**：角色含头身高约 108px，64×64 装不下。
> 112 = 108 + 2 底部余量 + 2 取整到 16 的倍数（112 = 16×7）。

### 2.1 检查帧内容的三个像素

拿到任何一帧，放大到 800% 看这三处，任何一处不对就是废帧：

1. **脚底**：靴底最低的一行像素，必须在 y=109。缺 1px 就会在播放时"踩空"。
2. **头顶**：最高一行像素，理想在 y=4~9（身高 100~105px）。
3. **身体中线**：躯干左右边缘的中心，理想在 x=32±1。

## 4. 交付后处理与校验（工程侧，已就绪）

### 4.1 归一脚本（已经把现有 24 帧修好了）

`Tools/normalize_walk_frames.py` —— 把任意尺寸的行走帧统一到 64×112，脚底对齐到 y=109。

```bash
# 校验（不改文件）
python3 Tools/normalize_walk_frames.py Assets/Art/V2/Characters --check

# 归一输出到新目录
python3 Tools/normalize_walk_frames.py Assets/Art/V2/Characters --out Assets/Art/V2/Characters_norm
```

**本次实跑结果**：

```
画布 64x112 ｜ 脚底基线 y=109（底部留 2 px）
全部合规：24 帧统一到 64x112，脚底同在 y=109
```

**它做了什么**：按 alpha 包围盒裁出主体 → 水平居中到画布中线 → 底边贴到基线 → 其余补透明。
**它没做什么**：不缩放、不重绘、不修内容（**草帽问题它修不了**）。

> 为什么不做缩放：像素游戏缩放会产生非整数像素密度，反而更糊。
> 归一只是"把尺寸不同的图放进同一个相框"，让角色不再横跳。

**重画流程建议**：

1. 先跑一次 `--check`，确认当前状态；
2. 重画的新帧（无论什么尺寸）丢进同一个目录；
3. 跑归一，输出到 `Characters_norm/`；
4. 再跑 `--check` 验收 —— **退出码 0 才算过**；
5. 跑一致性校验，然后人工确认（见 §4.2）。

### 4.2 一致性校验脚本 `Tools/check_walk_consistency.py`

把第二批需求验收第 ⑧ 条（「24 帧并排看，特征不一致即废帧」）自动化。
它查四件事：几何（画布/脚底基线/居中）、硬边、**跨帧调色板漂移**、方向离群。

```bash
python3 Tools/check_walk_consistency.py Assets/Art/V2/Characters \
        --canvas 64x112 --baseline 109
```

**原理**：先算出「被该角色多数帧共有的基调色」，再逐帧找「占比显著但多数帧没有」的游离色。
黄草帽这种凭空多出来的配件，会在这一步暴露。

**在现有那套帧上的实测输出**（它确实逮到了）：

```
角色 (未标角色)（24 帧）｜角色基调色 9 个（被 ≥14 帧共有）
  ⚠ 色 #D08000 占比最高 5.3%，仅出现在 6 帧、方向 [up]：
     v2_walk_up_01 ... v2_walk_up_06
  ⚠ 色 #D07000 占比最高 4.6%，仅出现在 6 帧、方向 [up]
  ⚠ 色 #C07000 占比最高 4.5%，仅出现在 6 帧、方向 [up]

【④ 方向离群】
  down=0.54  up=0.25  left=0.46  right=0.54
  ⚠ 方向 [up] 与其余方向调色板重合仅 0.25，明显离群 —— 优先人工并排核对

退出码 3
```

`#D08000 / #D07000 / #C07000` 就是那顶橙黄草帽，`up` 方向同时被判定为离群。
**退出码 0 = 过，3 = 退回重做**，可直接挂进流程当闸门。

> 局限：调色板漂移是「疑似」判定。若某方向本就有合法差异（背面才看得见的披风、
> 只在该方向出现的道具），会误报，需人工确认后放行。

## 7. ⚠️ 命名变更带来的集成缺口（必须先定，再画）

**现状**：`GameSceneBuilder.EnsureWitchAnimations()` → `EnsureWalkClip(dir)` 只做一件事——
用 `v2_walk_{dir}_{01..06}.png` 生成 `witch_walk_{dir}.anim` 四个剪辑，
交给唯一的 `WitchPlayerController`。**四个可玩角色共用这一套帧**（所以女巫现在走的是农夫的动作）。

**要按角色区分，缺的不只是命名**：

| 缺口 | 位置 | 说明 |
|---|---|---|
| 路径拼接要加角色段 | `GameSceneBuilder.EnsureWalkClip()` | 现写死 `v2_walk_{dir}_{i:00}.png`，需按角色拼 |
| 剪辑要 ×4 | `Assets/Animations/` | 现有 4 个 `witch_walk_*.anim` → 需要 16 个（4 角色 × 4 方向） |
| 控制器要 ×4 | 同上 | 现有 1 个 `WitchPlayerController` → 每角色一个，或一个控制器参数化 |
| 按角色挂载 | `PlayerAppearance` / `CharacterAnimDriver` | 现有逻辑只认「女巫有动画、其余走 flipX+bob」，需改成按 characterId 选剪辑 |

> 这几项**都不在《第二批需求》§八「交付后的工程侧处理」里**，但缺了动画就接不上。
> 建议：**先定命名与剪辑组织方式，再让美术动笔**，否则 96 帧画完还要再谈一轮。

**两个可选方案**：

- **A（推荐）**：命名带角色段 → 按角色生成 4 套剪辑 + 4 个控制器。
  改动量中等，但这是「4 个角色各自有独立动作」唯一干净的做法。
- **B（省事但受限）**：沿用无角色段的命名，做成「按当前角色整组替换 24 张图」。
  代码改动最小，但**同一时刻只能存在一个角色的行走图**，无法支持后续 NPC。

> 建议交给 `cocos-engine-expert`；我这边负责素材规格、归一与校验。
