## v0.11 — 2026-10-17 · 修复「安卓端完全无法移动」+ 屏幕虚拟摇杆

**用户实测反馈**：APK 装到手机上，登录、选角都正常，进农场后**没有任何方向键，动不了**。

### 1. 根因

`FarmScene` 从建立起就**没有 Canvas、也没有 EventSystem** —— 它只有相机 / Tilemap / 物件 / 边界 / 玩家。
而移动唯一的输入源是 `PlayerController` 里的 `Input.GetAxisRaw("Horizontal"/"Vertical")`，即**键盘轴**。

手机上没有键盘，也没有 EventSystem 去派发任何指针 / 触摸事件，
所以「没有方向键」不是 UI 漏画，而是**这个场景从来就没有任何可用的移动输入**。
（登录场景有 Canvas + EventSystem，所以登录 / 选角按钮一直是好的 —— 这也解释了「能进游戏但进去动不了」。）

| 检查项 | 结果 |
|---|---|
| 全工程 `Input.` 调用点 | 仅 `PlayerController.cs` 2 行，无触摸分支 |
| 全工程触摸 / 摇杆相关代码 | **零** |
| `FarmScene` 实际节点 | 8 个功能节点 + 25 个布景，**无 Canvas / EventSystem** |
| `Assets/Art/V2/UI/` 摇杆素材 | **无** |

### 2. 修复

| 层 | 改动 |
|---|---|
| **新增素材** | `Tools/gen_ui_joystick.py` → `v2_ui_joystick_base.png`（288×288 空心环）/ `v2_ui_joystick_knob.png`（128×128 木纹圆盘）。配色取自 `luminous_pixel` 木纹族，与 `v2_ui_button_wood` 同源；底圈做**空心**是因为硬边规范禁止半透明，实心会遮掉一大块画面 |
| **新增输入层** | `Assets/Scripts/Controls/MoveInput.cs`（静态汇聚层）+ `VirtualJoystick.cs`（指针事件 → 方向向量）。`PlayerController` 改读 `MoveInput.Read()` |
| **新增 HUD** | `GameSceneBuilder.BuildFarmHud()`：农场场景补上 Canvas（1920×1080 / 按高度适配）+ EventSystem + 左下角虚拟摇杆。画布规范与登录界面完全一致 |
| **新增校验** | `Tools/check_farm_hud.py`：只读场景 YAML，离线校验 15 项结构（不用开编辑器） |

**手感要点**：
- 键盘与摇杆**取幅度大的那一路**，不相加 —— 相加会让斜向顶到底归一化后单轴掉到 0.71，斜走比直走慢；
- 死区 0.18，过死区后线性重映射，跨死区从 0 平滑起速；
- 只跟**第一根按下的手指**，第二根手指不抢；
- `OnDisable` / 松开时清零 `VirtualAxis`，避免切场景后角色「鬼走路」；
- 触摸热区 480×480（隐形），比底圈 288 大一圈，手指不用瞄准圆环。

### 3. 兼容性

键盘 / 手柄/ 编辑器手感与改之前**逐位一致**；`hideOnNonTouchDevice` 默认关闭，所以摇杆在 PC 上也显示
（便于在编辑器里用鼠标拖动验证），要隐藏勾一下即可。

### 4. 验证

- `Tools/CompileCheck` 离线编译：**0 错误 0 警告**。
- 摇杆素材自检：尺寸 / 硬边（半透明像素 0）/ 几何探针全部通过。
- `Tools/check_farm_hud.py`：**必须先重跑一键生成**才会 PASS（旧场景正确判 FAIL，已实测）。

> ⚠️ **本次修复必须重跑场景生成才生效。** `BuildFarmHud()` 只在生成时执行，
> 已存在的旧 `FarmScene.scene` 不会自动补 Canvas。
> 另外 `BuildAll()` 第一步是 `SaveCurrentModifiedScenesIfUserWantsTo()`，
> 弹窗点 Cancel 会**整个中止**（表现为「只有素材被重导、场景没变」）。

详见 `Docs/LuminousSSS-移动端输入规格.md`。

## v0.9.1 — 2026-10-16 · 修 `verify_hardedge.py` 静默 bug + 新增行走帧一致性校验

### 1. 修 bug：`verify_hardedge.py` 传多个目录时输出全空（第二批需求 §八 提到的那条）

复现后确认根因是个**静默失败**：

- 旧版把 `sys.argv[1]` 当「根目录」，再拼出 `<根>/UI`、`<根>/Items`……
  所以传多个目录时（`verify_hardedge.py Assets/Art/V2/UI Assets/Art/V2/Items`），
  它实际去找的是 `Assets/Art/V2/UI/UI` 这类不存在的路径；
- 而旧版对「目录不存在」是 `if r is None: continue` **静默跳过** ——
  输出整个为空、也不报错，看起来像「扫了但没素材」。

新版：显式接收任意多个目录（`--root` 则扫标准子目录）；目录不存在**明确报错**并非零退出；
超阈值文件**逐张列出**；退出码 0 全过 / 1 参数错 / 2 目录问题 / 3 有超阈值。

实测（对 v0.8 那 50 张）：

### 2. 新增 `Tools/check_walk_consistency.py`：把验收第 ⑧ 条自动化

第 ⑧ 条要求「同一角色所有帧并排看，特征不一致即废帧」，24 张肉眼比对很累且容易漏。
新脚本一次查四件事：几何（画布 / 脚底基线 / 居中）、硬边、**跨帧调色板漂移**、方向离群。

**原理**：先算出「被该角色多数帧共有的基调色」，再逐帧找「占比显著但多数帧没有」的游离色。
凭空多出来的配件（帽子、披风）会在这一步暴露。

**对仓库现有 24 帧的实测 —— 确实逮到了那顶草帽**：

```
【③ 跨帧调色板漂移】
  ⚠ 色 #D08000 占比最高 5.3%，仅出现在 6 帧、方向 [up]：v2_walk_up_01 … v2_walk_up_06
  ⚠ 色 #D07000 占比最高 4.6%，仅出现在 6 帧、方向 [up]
  ⚠ 色 #C07000 占比最高 4.5%，仅出现在 6 帧、方向 [up]

【④ 方向离群】
  down=0.54   up=0.24   left=0.46   right=0.54
  ⚠ 方向 [up] 与其余方向调色板重合仅 0.24，明显离群

【①② 几何】24 帧画布均 64×112、脚底均 y=109、居中偏移 ≤1px —— v0.9 的归一有效
【硬边】24 帧半透明 16.7%~20.5%，仍待硬边化（即 2D-01）
```

退出码 0 = 过，3 = 退回重做，可直接当流程闸门。

> 局限：调色板漂移是「**疑似**」判定 —— 合法差异（只在背面看得见的披风、只在该方向出现的道具）
> 会误报，需人工确认后放行。

### 3. ⚠️ 查出一处规格冲突：行走帧命名与代码不一致

第二批需求 §3.1 要求命名 `v2_walk_<角色>_<方向>_<nn>.png`（**带角色段**），
而 `GameSceneBuilder.EnsureWalkClip()` 写死
`V2/Characters/v2_walk_{dir}_{i:00}.png`（**无角色段**）。
**按文档命名交付，程序一个文件都找不到**，只会刷「缺少行走帧」警告。

且现有集成是**女巫专用**：只有 4 个 `witch_walk_*.anim` + 1 个 `WitchPlayerController`，
四个可玩角色共用同一套帧（所以现在女巫走的是农夫的动作）。
要真正按角色区分，除命名外还需：剪辑 ×4（16 个）、控制器 ×4、
`PlayerAppearance` / `CharacterAnimDriver` 改为按 characterId 选剪辑。

**这几项不在第二批需求 §八「交付后的工程侧处理」清单里。建议先定命名与剪辑组织方式，再让美术动笔** ——
否则 96 帧画完还要再谈一轮。详见 `Docs/LuminousSSS-角色动画帧规格.md` §7。

### 4. 帧数规格更正：每方向 4 帧 → 6 帧

本文档 v0.8 曾建议「每方向 4 帧（现有 6 帧里有 2 帧像待机帧）」。
现更正为 **6 帧/方向** —— `EnsureWalkClip()` 硬编码循环 6 次，交付 4 帧会报警且动画不完整；
